# OCR 전처리와 검증

## 원인과 수정

밝기 이진화는 색이 다른 가로선과 문자를 같은 전경으로 합칠 수 있다. 가장자리 투표는 이미지 테두리나 스크린샷 여백을 배경으로 오판할 수 있다. 색상 군집을 단순 면적으로 선택하면 안티앨리어싱 윤곽·잡음이 글자 내부 대신 선택된다.

RGB 색상 군집화로 색 정보를 보존하고 최대 면적 군집을 배경으로 본다. 나머지 군집마다 작은 연결 영역을 제거하고 글자 높이를 가진 영역의 면적을 비교한다. 얇고 넓은 선은 이 점수에 포함하지 않는다. 선택한 마스크를 검은 글자와 흰 배경으로 변환해 OCR에 전달한다. 결과는 검증된 정답이 아닌 인식 후보로 표시한다.

## 참고한 오픈소스

- [OpenCV 색상 양자화 예제](https://github.com/opencv/opencv/blob/2ba4647c89601a4bbf1b73c123f700aef88c72bf/doc/py_tutorials/py_ml/py_kmeans/py_kmeans_opencv/py_kmeans_opencv.markdown#L166-L175): RGB 픽셀을 군집화하는 접근. 라이브러리 코드를 복사하거나 OpenCV 전체를 번들에 추가하지 않았다.
- [Tesseract ImproveQuality](https://github.com/tesseract-ocr/tessdoc/blob/b2d57fcf3dcce5cb53743562c35a9aaeeb57d918/ImproveQuality.md#L22-L53): 입력 전처리와 밝은 배경/어두운 글자 정규화. 전경 군집 선택 기준은 이 프로젝트의 휴리스틱이며 공식 OCR 알고리즘이 아니다.

## 재현

프로젝트 루트에서 `python3 -m http.server 18770 --bind 127.0.0.1` 실행 후 Chrome으로 `http://127.0.0.1:18770/tools/ocr-regression.html`을 연다. 두 스크린샷에서 추출한 4개 픽스처와 다른 색 조합의 합성 이미지 3개를 실제 번들 OCR 엔진으로 검증한다. 완료되면 `document.body.dataset.result`가 `pass`여야 한다.

기존 밝기 처리: 이전 표본 1배 BLKPKU / 2배 s ur, 새 표본 1배 빈 결과 / 2배 JN. 색상·연결 영역 처리 후 네 경우 모두 기대 문자열과 일치했다. 스크린샷에서 추출한 이미지이므로 실제 원본 data URL의 sd15 결과를 정확히 재현한 것은 아니다.

## 한계 및 후속 검증

픽스처는 수정에 사용한 회귀 표본으로 랜덤 캡챠 정확도의 추정 자료가 아니다. 별도 랜덤 원본 이미지와 정답으로 측정해야 한다. 배경이 최대 면적이고 문자색이 일관적인 경우를 대상으로 하며, 다색 문자·동일색 방해선·복잡한 배경에서는 실패할 수 있다. 인증 제출이나 서버 보안을 검증하지 않았다.

## 자동 입력 검증

같은 서버의 `/tools/capture-input-regression.html`은 실제 DOM에서 자동 시작 요청, 입력값 및 input/change 이벤트, 이미지 변경 시 이전 자동값 제거, 오래된 결과 거부, 수동 입력 보호, 숨겨진 팝업 및 교체된 입력칸 보호, 제출 클릭 없음 등을 검증한다. Chrome runtime 포트는 테스트 대역이므로 설치된 확장의 권한·포트 연결 및 실제 사이트의 React 상태 반영까지 입증하지는 않는다. 기존 OCR 큐는 원본 이미지와 세대 번호를 결과에 전달하고 페이지 측에서 입력 직전 다시 확인한다.
