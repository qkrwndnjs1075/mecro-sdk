- 예매 오픈 대기 기능은 사용자가 실제로 기다릴 판매 전 페이지에서 검증한다. 이미 판매 중인 공연의 회차 복원 테스트로 오픈 전 진입을 검증했다고 판단하지 않는다.
- 미오픈 화면의 유형을 조사할 때는 공식 오픈 예정 목록의 끝까지 확인한다. 상품 상세 화면, 예매 진입 화면, 판매 차수별 상태를 각각 기록하고 확인한 범위를 명시한다.
- 확장 기능은 사용자가 실행할 브라우저에서 검증하고 대상 OS를 구현 전에 확인한다.
- HTML의 data URL 추출 요청은 로컬 파일 선택과 구분한다. 대상 URL을 모르면 사용자가 선택한 현재 탭의 activeTab 권한으로 처리할 수 있는지 먼저 확인한다.
- OCR 실패가 반복되면 전처리된 픽셀을 먼저 확인한다. 색상 군집의 면적만으로 문자를 선택하지 않고 잡음·연결 영역을 함께 평가한다. 같은 실패 표본을 여러 크기에서 회귀 검증하고 비어 있지 않은 결과를 정답 검증 성공으로 표시하지 않는다.
- 자동 실행 요청은 확장 버튼을 누르지 않은 상태에서 검증한다. 실제 호스트·프레임·권한과 설치 확장의 연결을 확인하지 않고 DOM 대역 테스트만으로 자동 실행 완료를 판단하지 않는다.
- 자동 OCR을 비활성 UI 탭의 렌더링·포트 생명주기에 맡기지 않는다. 화면에 독립적인 실행 컨텍스트에서 처리하고 설치 확장으로 창 전환 없는 콜드 시작을 확인한다.
- OCR confidence는 정답 확률이 아니다. 오답의 confidence가 높아질 수도 있으므로 실제 문자열을 대조하고, 후보 비교 비율 같은 경험적 설정의 검증 범위를 명시한다.
- 인식 보류는 오인식 자체의 수정과 구분한다. 정확도와 속도를 함께 개선했다는 보고에는 수정에 쓰지 않은 표본의 전체 문자열 정답률과 동일 조건의 처리 시간 비교가 필요하다. 후보 일치 여부와 최종 입력 여부도 별도로 기록한다.
- 자동 입력에 합의·형식 조건이 있으면 회귀 검사는 후보 문자열뿐 아니라 그 조건을 통과해 전달되는 문자열까지 검사한다. 테스트의 워커 설정도 운영 생성 함수를 재사용해 설정 복제로 인한 검증 누락을 막는다.
- 신규 실패 표본이 나오면 고정 크기나 후보 비율을 다시 조정하기 전에 전처리 픽셀과 두 원시 후보를 확인한다. 기존 회귀 표본에서 고른 설정을 일반적인 해결로 표현하지 않는다.
- 실사용에서 실패가 반복된다는 보고가 있으면 한 번의 성공으로 해결을 선언하지 않는다. 검증 결과에는 관찰한 범위를 명시하고 반복 실패의 원인이 확인됐는지 별도로 기록한다.
- 획 복구 실패를 연결 영역 조건 탓으로 단정하기 전에 방해선 마스크에 해당 선이 실제 포함되는지 확인한다. 기울어진 선의 바운딩 박스 높이는 선 두께가 아니다. 브라우저 비교는 캐시된 이전 모듈이 아닌 현재 파일을 실행하는지도 확인한다.
- OCR 설정 변경은 새 실패 원본과 기존 실패 표본을 함께 비교한다. 한 표본을 고치고 다른 표본을 깨뜨리는 변경은 적용하지 않는다. 문자 추가 오류는 엔진의 문자 좌표까지 확인하고, 회귀 성공과 별도 스트레스 실패를 함께 보고한다.
- 사용자가 서브 에이전트 사용을 금지하면 일반적인 위임 지침보다 그 범위를 우선한다. 이미 시작한 서브 에이전트는 즉시 중단하고 이후 조사·수정·검증은 직접 이어간다.
