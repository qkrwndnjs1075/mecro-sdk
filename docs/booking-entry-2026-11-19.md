# 78LIVE 일반예매 진입 확인

18:14 KST에 Aside에서 해당 공연의 게이트와 활성 예매하기 버튼을 확인했다. 확인 시점에 별도 예매 탭은 없었다. 기존 확장은 버튼 호출 전 게이트 상태를 완료로 저장했고, 회귀 검사는 클릭 횟수만 검사했다. 이 기록만으로 18:00 당시의 클릭 전달 여부, 창 차단 여부, 창이 열렸다가 닫혔는지는 판별할 수 없다.

- 수정: 상품과 게이트 모두 버튼 호출을 이동 시도로 기록한다. 기존 탭의 이동 또는 시도 직후 원본 탭이 만든 새 탭의 이동이 지원 대상 주소에 도달해야 확인 상태를 기록한다. 빈 자식 창 생성만으로 완료 처리하지 않는다.
- 검증: `node --test tools/booking-navigation.test.mjs` 및 `tools/wait-cancellation-regression.html`의 normal, cancel, failed-save, failed-clear 시나리오. 클릭만 일어난 경우와 게이트 또는 좌석 화면 이동이 관찰된 경우를 구분한다.
- 후속: 다음 실제 오픈에서 대기 시각과 새 창 생성·이동 여부를 함께 확인한다. 관찰하지 않은 대기열 주소와 브라우저 차단 사유를 추정해 성공 처리하지 않는다.

## 20시 네메시스 후속 확인

20:00:22의 화면에는 게이트와 이동 미확인 안내가 남아 있었다. 이후 Aside 탭 목록에서 NOL의 `/waiting`과 `/onestop/seat`를 차례로 관찰했다. 당시 클릭 전달 기록과 탭 사이의 이동 이력이 없어 자동 진입 여부는 미확정이다.

- 수정: 버튼의 클릭 이벤트 전달 여부를 시도별로 기록한다. 백그라운드는 같은 탭과 연결된 자식 탭에 같은 대기열·좌석 화면 판별을 적용한다. 대기열 URL의 쿼리는 저장하지 않는다.
- 회귀 검사: Chrome의 기본 팝업 차단에서 타이머 클릭이 1회 전달돼도 창이 열리지 않는 경우를 재현했다. 같은 탭과 새 탭의 대기열→좌석 이동은 내비게이션 이벤트 대역으로 검사했다.
- 후속: 수정본을 설치한 실제 오픈에서 클릭 전달 기록과 대기열·좌석 도착 기록을 함께 대조한다. 이번 실사이트 실패를 팝업 차단으로 확정할 증거는 없다.

## 11월 20일 세종 공연

08:53:54부터 09:01:35까지 수집한 게이트 버튼 상태는 ‘남은시간 06:12’, 비활성이었다. 오픈 시각 이후에도 대기열·좌석 탭은 관찰되지 않았다. 사이트의 카운트다운이 정지한 원인과 그 시점의 확장 내부 상태는 이 관찰만으로 특정할 수 없다.

- 수정: 기존 게이트 대기는 예정 시각이 지나도 현재 문서에서 버튼을 무기한 찾았다. 예정 시각에 활성 버튼이 없으면 상태를 저장하고 게이트를 한 번 다시 로드한다. 재개한 문서에서는 활성 버튼을 기다리는 시간을 제한한다. 같은 버튼 탐색 루프를 사용하는 상품 상세에도 이 종료 조건을 적용한다.
- 검증: `node --test tools/stalled-gate.test.mjs`로 예정 시각 전에는 새로고침하지 않는 경우, 새로고침 후 활성화되는 경우, 계속 비활성인 경우의 클릭·새로고침 횟수와 최종 상태를 검사한다.
- 후속: 다음 실제 오픈에서 설치 확장의 대기 시작 상태, 새로고침, 버튼 활성화, 최종 이동을 함께 확인한다. 이 수정으로 이전 두 공연의 클릭 이후 이동 문제까지 해결됐다고 판단하지 않는다.
